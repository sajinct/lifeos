# Controlled document sharing

Open **Documents & receipts → Document sharing**. Choose one completed personal-document version and one current workspace member. Only the uploader with workspace write access can create or restore a share; a workspace owner cannot share another member's private files. Recipients, including viewers, can download that version. Receipts cannot be shared here. Granting a newer version is a separate action; archiving a completed version preserves its existing grants.

Use **Shared with me** for downloads and **Shared by me** for revocation. **Including revoked** shows the uploader's history and permits explicit restoration for current members. Uploaders who are downgraded to viewer can still revoke existing shares. Removing either the uploader or recipient automatically revokes active grants. Rejoining never restores those grants automatically. Revocation blocks later downloads, including a grant revoked during the server's Storage fetch. Copies already downloaded or responses already in transit cannot be recalled.

Sharing publishes only filename, MIME type, size, version number and sender/recipient display names. It does not expose full attachment rows, other versions, expiry dates, categories, private project links or Finance links. Received metadata is fetched on entering the screen or **Refresh access**. Cached display information is not proof of continuing access: every download checks the current server grant. All catalog pages are loaded by stable ID. Completed private-file choices also use full stable pagination. Demo shares and the demo reader are simulated, scoped to the current session and send no invitations or messages.

## Deployment and authorization

Apply `202610140009_document_sharing.sql`, deploy `document-download` with `supabase functions deploy document-download --project-ref eyrqbrxohwekzizuairz`, then run `scripts/document-sharing-cloud-smoke.sql` through the linked database query command. The function uses Supabase's built-in server URL/service key; no new client secret is needed. `verify_jwt = false` disables the legacy gateway check only: the handler verifies every caller against `/auth/v1/user` and invokes the download RPC with that caller's JWT. Missing/invalid tokens are rejected. Only its Storage byte fetch uses the server key.

The browser has SELECT-only grant metadata and authorized RPCs. Attachment and Storage RLS remain private to uploaders. Recipients therefore cannot bypass revocation by creating Storage signed URLs. The proxy checks the grant before fetching and again after fetching, compares the revision/path/size, limits documents to 10 MiB and returns an octet-stream attachment with `Cache-Control: no-store, private`. It exposes no reusable URL and accepts no caller-supplied Storage path. This choice follows Supabase's documented [private Storage download modes](https://supabase.com/docs/guides/storage/serving/downloads) and [server-side user verification](https://supabase.com/docs/reference/javascript/auth-getuser).

Membership locks precede the workspace advisory lock (seed 43), file and grant row locks. This makes grant changes serialize with member removal without reversing the deletion trigger's lock order. Exact successful request receipts live in a private table and cannot undo newer revocation. Current authentication, role, file ownership and membership are checked before receipt replay. Each version retains at most 200 recipient records including revoked history. Bindings cannot change and `(attachment_id, recipient_id)` stays unique.

Full database backups retain grants and private request receipts. Private Storage bytes remain a separate backup. Local recovery checks restore grants, exact retries and revoke/restore while preserving attachment privacy. Workspace JSON exports currently omit the sharing catalog; they are not a full database recovery or grant importer. A hosted Auth/Storage recovery drill still requires a disposable staging project. The hosted SQL smoke tests metadata and authorization in a rollback; it does not transmit or restore real Storage bytes.
