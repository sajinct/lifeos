# LifeOS architecture and milestones

## Delivery boundary

Phase 1 provides a deployable Angular shell, real Supabase authentication, profile editing, workspace creation and switching, access control, private Storage, and a dashboard. A small end-to-end slice of Phase 2 (tasks, projects, calendar, notes, goals and expense capture) makes dashboard actions useful. Remaining ERP domains are roadmap work, not empty routes.

## Conventions

Angular 22 standalone components, strict TypeScript, signal state, lazy routes, reactive forms and Tailwind. Components render state and delegate mutations to typed repositories. No application API server. Browser configuration contains only the Supabase URL and publishable key. Hash routing supports GitHub Pages. The PWA caches build assets only; no API responses or user uploads.

## Ownership and schema

Every domain record has a UUID, workspace_id, owner_id, visibility, timestamps and foreign keys. Visibility defaults to private. A private record is readable/editable by its owner, provided that user remains a workspace member; a shared record is readable by members and editable by its owner or workspace owner. Viewers cannot create or edit. The workspace owner alone manages membership through an authorization-checking RPC. Direct ownership, workspace and role mutations are disallowed by column grants and RLS. Profiles and preferences are personal. Member identity is available through memberships; other users' profiles remain private.

Projects connect tasks, events, notes and transactions through composite foreign keys including workspace_id. A database trigger additionally verifies that a creator can access linked projects. Finance uses NUMERIC(14,2); account transfers use a single authorized PostgreSQL RPC and deterministic row locking. Account balances derive from immutable ledger entries, never client-side running totals.

Foundation: profiles, workspaces, workspace_members, categories, tags, entity_tags, attachments, reminders, notifications, activity_logs, app_settings. Working slice: projects, tasks, calendar_events, notes, goals, accounts, transactions. Additional domains will get normalized schemas with their own reviewed migrations at implementation time.

Finance planning adds private budgets, bills and recurring_transactions. Budgets match category, calendar month and account currency against the complete visible expense ledger. Bill posting locks the bill, inserts one linked expense and stores its transaction ID in the same transaction. Recurrence posting locks each schedule and uniquely identifies occurrences by schedule/date. Dates are calculated from the original anchor so January 31 returns to March 31 after February. Only the record owner with write access may post or pause; service-only automatic dispatch also checks the owner's current membership. Browser clients cannot change payment state, occurrence counters or posting dates. Plans default to manual posting, with explicit opt-in automatic hourly dispatch through Supabase Cron.

## Shared UI

The private file library reserves attachment metadata before uploading immutable bytes to Storage. Completion checks actual object size/type and promotes the reservation through an owner-authorized RPC. A new version links to its predecessor and archives it only after successful upload. Archives preserve bytes and can be restored; only unfinished/cancelled uploads can be cleaned up. Receipts may link to an immutable ledger entry owned by the uploader in the same workspace. Downloads use the authenticated Storage API, rechecking current membership rather than exposing a reusable signed/public URL. Responses bypass the browser HTTP cache. Downloaded bytes and temporary download URLs stay out of shared record signals, exports and PWA caches; file selections are transient form state. Demo blobs are memory-only and cleared with the session.

Responsive navigation, icons, toast feedback, accessible quick-add dialog, command/search dialog, theme switch, offline status, validation states and reusable record views. Dashboard widgets can be hidden in Settings. Demo records are synthetic and live only in memory; real records are never written to browser application caches.

## Milestones

1. Foundation and reviewed RLS migrations; runnable shell and dashboard.
2. Auth, profile, workspace onboarding, settings and backend repositories.
3. Working task/project/calendar/note/goal/expense slice; useful dashboard interactions.
4. Production/PWA builds, meaningful unit tests and database isolation tests, CI deployment and operating documentation.
5. Finance planning: private category budgets, bills and anchored recurring income/expenses, tested for isolation and retry-safe ledger posting; opt-in hourly automation through Supabase Cron.
6. Private files: document and receipt uploads, category/expiry filters, authenticated downloads, versions, archives, project/ledger links and interrupted-upload recovery. Database and live Storage API isolation tests cover the lifecycle.
7. Personal, opt-in in-app reminders for task dates, pending bills and document expiry. A service-only five-minute dispatcher uses each user's IANA time zone, lead times and local delivery hour. Unique source/date/phase keys and a scheduler lock prevent duplicates. Notifications stay private to the record owner, support read/dismiss/snooze, and link to their source. Completion, payment, archival and date edits clear stale occurrences; removed members cannot read or act on reminders. Browser polling loads the newest 100 active/snoozed notices for the current workspace, with session guards against stale responses. Demo reminders follow the same calendar rules in memory. Live cloud SQL checks are fully rolled back.
8. Private subscription/trial tracking with normalized monthly/yearly estimates separated by currency. All subscription writes use owner-authorized RPCs; direct table writes are denied. A stable creation UUID and transaction advisory lock make retries create one expense schedule. Linked prices/cursors come from the owned monthly/yearly expense schedule. Cursor synchronization and cancellation lock schedules before subscription rows, matching posting order. Trials stay paused; cancellation disables active/automatic flags and prevents direct resume. Replacement/disconnection pauses the old schedule and retains ledger history. Tracking-only acknowledgements use expected dates for replay safety and preserve original month-end anchors. Trial and renewal reminders use separate source kinds, with existing personal delivery preferences extended by an opt-in subscription toggle. The older reminder-settings RPC remains compatible. Full subscription pagination supports complete currency estimates; linked plans outside the loaded window are fetched by owner/workspace before actions.
9. Private loans and immutable repayments. Owner-only RPCs compute a fixed simple-interest contract (principal × annual rate × monthly term / 1200), cent-rounded monthly installments and anchored due dates. Principal cash movements use transfer ledger kinds; interest alone is income/expense. Creating a loan and recording a repayment have separate request UUID advisory locks, and repayments lock the loan before validating remaining principal/interest. Retries cannot post twice, and concurrent payments cannot overpay. Account ownership, workspace/currency and membership/write permissions are checked in the transaction. Optional tracking-only mode records no ledger entries, allowing payments already captured elsewhere. Cumulative payments advance the schedule only after an installment is covered; full repayment clears the next date and stale alerts. Loan/repayment tables have owner/membership SELECT policies and no direct browser write grants. All rows are paginated for balances, history and exports, with session guards. Loan reminders extend the five-minute dispatcher and preserve both older reminder RPC overloads. Bank EMI amortization, compounding, rate changes and early-settlement interest reductions remain future work.
10. Read-only Finance reports aggregate the complete owned ledger, accounts and budgets by booking date and currency. Income/expenses define net savings; external loan-principal movements additionally define cash flow, while internal transfers stay excluded. Inclusive date filters cover up to 120 calendar months and zero-fill months. Category comparisons use the immediately preceding equal-length period. Budget actuals use the selected dates against full monthly limits without prorating. Loan interest and subscription expenses are subsets of the same ledger totals. Permanent transaction subscription IDs preserve attribution when a schedule is disconnected/replaced; owner/workspace guards apply to tagging and backfill, and browser ledger write grants stay denied. Historical disconnected plans predating attribution may remain unclassified. The CSV export includes the current filtered summaries and ledger, with formula-neutralized labels; exports are disabled for invalid ranges or incomplete/erroring loads. No report data is persisted in browser caches or new backend views.
11. Private Contacts and contact_links add person/organization details, notes, follow-up and last-contact dates. All writes use owner-authorized RPCs; creation UUID advisory locks make retries stable, and integer revisions prevent lost edits. Link replacement is atomic and validates target owner/workspace before changing either metadata or relationships. Contacts can link up to 50 owned projects and 50 owned loans without changing target ownership, loan terms or sharing. Archives retain contact data/links and stop reminders; restoration preserves records. Completing a follow-up stores the owner's local date, clears the current reminder and is retry-safe; stale completion cannot clear a newly scheduled follow-up. Full contact/link pagination supports search and exports, and the contact form pages owned project options rather than truncating them to the generic project view. Direct source links fetch inaccessible-window project records by owner/workspace before navigation. Contact reminders extend the service-only dispatcher while retaining the 8/10/12-argument settings RPCs. Contact email/phone fields are stored/displayed without sending messages or syncing external address books. Demo data remains memory-only and workspace/session isolation guards all asynchronous reads/writes.
12. Family & household adds household_members and household_entries (responsibilities / important dates). Records default private; explicit workspace sharing uses existing membership, owner/editor/viewer rules, without creating identities or invitations. Household members store name, relationship, month/day birthday and notes; they are labels for responsibilities, not permission grantees. Shared entries may link only to shared members, and a member cannot become private while any shared entry retains its link. Workspace-scoped advisory locks serialize link/visibility changes, and integer revisions protect edits/completion from stale clients. Creators alone change sharing; workspace owners may edit shared content, other editors/viewers may read it. Direct browser writes are denied. Birthdays and annual dates compute the next calendar occurrence in the personal reminder time zone, preserving February 29 anchors and observing February 28 in non-leap years. The existing dispatcher sends private opt-in alerts only to creators who remain members; completion/archive and date changes clear stale notices. Legacy reminder RPCs preserve family settings. Complete pagination, guarded session/workspace loads, filtered CSV and workspace JSON support this module. Demo records remain memory-only.
13. Private Assets adds assets, asset_documents, maintenance_plans and immutable maintenance_logs. All browser writes use owner-authorized RPCs. Asset advisory locks serialize metadata/lifecycle and schedule/service changes; creation/request UUIDs and integer revisions reject duplicate/stale operations. Document replacement validates completed ready/archived files by owner/workspace before atomic metadata/link updates, and composite foreign keys protect relationships. File links preserve the selected version and never alter Storage permissions. Maintenance frequencies are one-time, monthly or yearly; completion records scheduled/performed dates, optional reference cost/currency/title/notes snapshots and advances from the original anchor, preserving month-end/leap-day behavior. Changing next date/frequency starts a new anchor without deleting history; completed scheduled dates cannot be reused. Recording a cost does not post to Finance. Sold/retired/archived assets retain plans/files/history and stop notices; paused/completed plans are excluded. Warranty/service reminders extend the existing personal dispatcher with legacy settings compatibility. Full pagination, async workspace/session guards, exact file/source navigation and CSV/JSON exports cover the lifecycle; no API/file data enters PWA caches.
14. Private Career adds career_records and career_documents. Employment, applications and certifications use a fixed section with section-specific date/status validation. RPCs serialize by stable record UUID, authorize the owner and workspace write membership, enforce revisions and atomically replace owned completed document links. Direct browser mutations are denied; workspace owners cannot access member-private records. Date completion clears only the selected follow-up/interview with stale-action protection. Closed applications and archived records stop alerts; restoration of an archived application explicitly reopens it as applied. Reminders preserve existing opt-ins and dispatcher deduplication. Full pagination, session guards, exact source/file navigation and CSV/JSON exports follow existing boundaries. No automatic employment, Finance or external messages are created.
15. Goals & Habits adds habits, habit_periods, habit_checkins and goal_milestones. Existing goals gain period/status/notes/revision, and browser writes move to RPCs while retaining existing sharing and owner-controlled editing. New goal forms default private. Habits and milestones are owner/membership private, including under shared goals. Stable UUID creation, parent advisory locks and revisions prevent replay/lost-edit issues. Check-ins have a unique habit/date and reversible completion state with revision checks. Schedules are fixed; daily lifecycle periods retain active/paused/archived history and exclude inactive dates from statistics. Pausing/archiving applies to the local day and retains logs. Streaks count scheduled days, skip paused periods and allow today's incomplete occurrence; best streak is bounded to 90 calendar days and consistency to 30. Milestones have independent completion/date/notes and never alter numeric goal progress. Goals/habit history are fully paginated, exported to CSV/JSON and cleared/guarded by workspace/session. No sensitive data is added to PWA caches.
16. Tasks & Productivity adds private task_lists/task_series and parent-scoped task_checklist. Task status writes move to revision-checked RPCs; one-off capture retains restricted legacy column grants. Tasks gain protected list/series/index and trigger-maintained revision fields. Workspace advisory locks serialize checklist/configuration/completion/repeat state. A unique series/index and transactionally copied unchecked checklist guarantee one successor per completed occurrence, including retries/reopen. Original anchors preserve month ends/leap days. Pause keeps pending tasks; resume generates a missing successor for the latest completed occurrence. Recurrence stops at the supported 2100 boundary. Shared tasks keep existing edit roles and their checklist follows parent visibility; private lists/series cannot be attached to shared tasks. List archives keep links/history and prevent new assignments. All task data is fully paginated and session guarded, included in workspace JSON and filtered task CSV. No cron or external messages are added; recurrence is completion-driven.
17. Task assignments/time adds tasks.assignee_id with shared-only/current-member binding and membership-removal cleanup. Assignment never changes task access/edit roles. A scoped directory RPC returns only current member display names/roles, keeping profile RLS intact. Private task_time_entries use owner plus membership reads, no direct browser writes and owner/write RPCs serialized by user advisory lock. Stable requests replay creation/start without mutation, one active timer per owner/workspace prevents duplicates, and stop/void/restore use revisions. Timer timestamps come from the database; duration caps at 24 hours, with work date in the profile zone at start. Manual dates/duration/notes are validated. Known task/project names are snapshotted; task deletion detaches the reference and retains personal history. Time records remain private after task resharing and are fully paginated, cached only in demo memory, session guarded and included in CSV/JSON. Completed-only task/project totals exclude running/discarded sessions. No notifications, time-based billing or expanded permissions are introduced.
18. Projects & Planning adds project_milestones and private project_budgets. Projects gain trigger-maintained revisions and retry-safe metadata RPCs while retaining restricted legacy capture. Milestones follow parent read/edit permissions; completion is independent of tasks and project status, with completion dates in the acting user's profile zone. Completed projects must be reopened before milestone changes. Stable requests, parent locks and child revisions protect replay/edits/archive/restore. Shared linked tasks/events/notes prevent project privatization, with parent row locks serializing link checks. Any writer may plan a private budget on a readable project; even workspace owners cannot read another member's budget or financial ledger. Budget currency is immutable, one plan per owner/project/currency persists through archival, and amounts preserve cents. Expense attribution edits only project_id on an owned expense, with expected-link protection and no ledger/balance change. Reports compare lifetime linked expenses by account currency with active personal plans, preserve separate currencies, and combine visible task progress, active milestones and personal recorded time. Projects and both new tables are fully paginated, session guarded and included in JSON/CSV exports. Milestone alerts, shared financial plans, billing and exchange-rate conversion remain future work.
19. Private Health appointments adds health_appointments/health_documents with owner plus current-membership RLS, SELECT-only browser grants and owner/write RPCs. Stable request UUIDs, advisory row locks and revisions protect replay, lost edits and lifecycle actions. Date/time/status/text validation rejects future completed visits. Archives preserve visit status and immutable selected file-version links; restoration never silently reschedules a completed/cancelled visit. Atomic document replacement accepts only the owner's completed ready/archived metadata in the same workspace; underlying private Storage access is unchanged. Optional personal day reminders extend the existing five-minute dispatcher, time-zone/hour settings, deduplication and snooze/dismiss/source navigation. Completion, cancellation, archival and date changes clear stale notices; old settings RPCs preserve the new opt-in. All records/links use full stable pagination, workspace/session guards, memory-only demo caches and CSV/JSON exports. Appointment times are displayed as entered and do not schedule exact-time notifications. Fitness, measurements, medication schedules and medical-expense links remain future health slices.
20. Subsequent work: travel, deeper health/existing-module features and imports. Email delivery and optional MFA UI follow their own security and integration tests. AI and external integrations come last.

## Deployment and operations

GitHub Pages is the requested production host. Sites hosting is not used. CI checks formatting, lint, unit tests and Supabase database tests before deploying an artifact. Local Supabase runs the same migrations and tests as production. Cloud resources and GitHub repository provisioning require the user's account configuration. PostgreSQL backups and private Storage object backups are separate, independently restorable operations.
